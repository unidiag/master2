# Master2

**Master2** — внутренняя веб-система кабельного оператора для учёта абонентов, заявок и подключений, контроля задолженности и отключений, обработки платежей ЕРИП, управления телевизионным оборудованием и автоматизации регулярных операций.

Проект продолжает развитие системы Master и работает с существующей базой **MySQL/MariaDB**. Серверная часть написана на **PHP без крупного фреймворка**, интерфейсы формируются серверными PHP-представлениями с JavaScript, а фоновые операции запускаются через PHP CLI и cron.

> **Версия документации:** [коммит `63e49f6ac7b917916982a31edb33da52acf4697c`](https://github.com/unidiag/master2/tree/63e49f6ac7b917916982a31edb33da52acf4697c) (15.10.2026 — дата актуализации README). Это описание кода указанной ревизии, а не обещание совместимости с последующими изменениями.
>
> **Назначение:** рабочий внутренний инструмент, а не готовый установочный пакет. Для запуска необходимы действующая структура БД, локальная конфигурация и настройка внешних сервисов.

## Возможности

Основные страницы доступны через `index.php?module=<имя>` после авторизации; права на отдельные разделы ограничиваются на сервере.

| Модуль | Адрес | Назначение |
| --- | --- | --- |
| Заявки | `?module=zayavki` | Учёт заявок, статусов и операций по абонентам |
| Подключения | `?module=podkluchki` | Регистрация и сопровождение подключений |
| Абоненты | `?module=database` | Поиск по абонентской базе, история начислений и оплат, фильтры |
| Статистика | `?module=stat` | Данные по домам и квартирам, задолженность, платежи и отключения |
| Отключения | `?module=otkluchki` | Отключения и восстановления с сохранением истории |
| Должники | `?module=debtors` | Анализ задолженности и связанных отключений |
| ЕРИП | `?module=erip` | Реестр платежей и статус синхронизации |
| Карандаш | `?module=karandash` | Заметки по абонентам |
| Строка | `?module=stroka` | Работа с объявлениями и записями |
| График | `?module=graph` | Статистика абонентов и тарифов |
| Аналог / Цифра | `?module=analog`, `?module=digital` | Разделы управления и учёта ТВ-оборудования |
| SMS | `?module=sms` | Отправка и контроль SMS через MTS Communicator |
| Money | `?module=money` | Финансовая статистика |
| Readers | `?module=readers` | Управление OSCam/Wicardd и конфигурациями ридеров |
| User stat | `?module=userstat` | Журнал пользовательской активности (администратор) |
| Отчёты | `?module=reports` | Формирование и рассылка отчётов |

### Абоненты, долги и отключения

Система использует исторические снимки абонентской базы. Это позволяет анализировать изменения задолженности, начисления и оплаты. В статистике дома можно перейти к конкретной квартире; для заявок и подключений предусмотрен контроль задолженности соседних квартир. Порог задаётся через `stat.nearby_debtor_min_debt`.

В таблице `master_otkluchki` активные отключения определяются по `deleted_at IS NULL`; признак `hidden_at` также учитывается при выборе уведомлений по оплатам.

### Readers

Административный модуль `readers` использует `app/ReaderService.php` для операций с OSCam/Wicardd: проверка состояния, запуск и остановка процессов, работа с конфигурациями и журналами. Основной cron проверяет процессы включённых ридеров и пытается восстановить отсутствующие.

Операции с процессами требуют правильно настроенных путей и прав пользователя ОС. Не предоставляйте управление ридерами неавторизованным пользователям.

## Архитектура

```text
master2/
├── index.php                    # Основная HTTP-точка входа
├── config.php                   # Загружает обязательный config.local.php
├── config.example.php           # Пример локальных настроек
├── config.local.php             # Рабочие настройки, секреты (не коммитить)
├── app/
│   ├── bootstrap.php            # Загрузка конфигурации, сессия, БД, сервисы
│   ├── Database.php             # Подключение через PDO
│   ├── Repositories/            # SQL-запросы и репозитории
│   ├── ReaderService.php        # Управление ридерами
│   ├── MtsSmsService.php        # Интеграция MTS SMS
│   ├── ReportService.php        # Работа с отчётами
│   ├── index/                   # Подготовка данных, действия, AJAX
│   │   ├── modules.php
│   │   ├── main_actions.php
│   │   └── ajax.php
│   └── views/modules/           # PHP/HTML/JavaScript отдельных модулей
│       ├── erip.php
│       └── readers.php
├── cron/
│   ├── cron1min.php             # Основной ежеминутный цикл
│   ├── check_erip.php           # Проверка оплат и отправка уведомлений
│   ├── cleanup_database.php    # Регламентное обслуживание БД
│   └── reports_monthly.php     # Плановая отправка отчётов
├── assets/                      # Статические ресурсы
├── terminal/                    # Служебный раздел
└── meteo.php                    # Страница погодных данных
```

Дерево показывает **ключевые** файлы и каталоги, а не полный список репозитория.

**Основной поток запроса:** `index.php` → `app/bootstrap.php` → обработчики в `app/index/` → данные/операции через PDO и репозитории → PHP-представление в `app/views/modules/`. Интерактивные действия выполняются через обычные запросы и AJAX.

## Требования

- Веб-сервер: Apache или Nginx с PHP.
- PHP **7.4+** (совместимость с используемой версией PHP следует проверить на реальном окружении).
- Расширения PHP: как минимум `PDO`, `pdo_mysql`; для задействованных интеграций также нужны `curl` и `mbstring`.
- MySQL или MariaDB со схемой и данными системы Master.
- PHP CLI и cron для регламентных задач.
- Доступ к внешним сервисам только по необходимости: Telegram Bot API, MTS Communicator, SMTP, устройства телевидения, файловый источник ЕРИП.
- Для генерации отдельных ресурсов и отчётов могут потребоваться `wkhtmltoimage` и библиотека PDF, используемая в конкретном окружении.

> В репозитории не предполагается универсальная автоматическая установка всей схемы БД. Не запускайте проект против пустой базы в ожидании автоматического создания таблиц.

## Установка и настройка

```bash
git clone https://github.com/unidiag/master2.git
cd master2

# Для точного воспроизведения описанной ревизии:
git checkout 63e49f6ac7b917916982a31edb33da52acf4697c

# Подготовить индивидуальную конфигурацию:
cp config.example.php config.local.php
```

После этого:

1. Заполните `config.local.php`: подключение к БД, пользователей, пароли, ключи и только необходимые интеграции.
2. Смените **все демонстрационные пароли и секреты** из файла-примера, прежде чем открывать приложение по сети.
3. Укажите веб-корень, в котором доступен `index.php`, и настройте PHP на сервере.
4. Запретите внешние HTTP-запросы к конфигурации, служебным скриптам и журналам.
5. Убедитесь, что существующая БД содержит требуемые таблицы и поля.
6. Проверьте начальную страницу, авторизацию и необходимые модули; cron подключайте только после настройки окружения.

Быстрые проверки синтаксиса и расширений:

```bash
php -v
php -m | grep -E 'PDO|pdo_mysql|curl|mbstring'
php -l index.php
php -l cron/cron1min.php
php -l cron/check_erip.php
```

## Конфигурация

**Источник рабочих параметров — `config.local.php`.** Файл `config.php` загружает его напрямую и выдаёт ошибку, если файл отсутствует. `config.example.php` служит образцом структуры.

| Группа | Что настраивается |
| --- | --- |
| `app` | Имя, часовой пояс, базовый путь, пагинация |
| `database` | Хост, порт, имя БД, пользователь, пароль, кодировка |
| `auth` | Авторизация, учётные записи и хеши паролей, длительность входа |
| `stat` | Порог задолженности в связанных проверках |
| `telegram` | Отправка уведомлений и получатели |
| `mts_sms` | Доступ к MTS Communicator, SMS-уведомления |
| `channels`, `digital` | Устройства и конфигурация ТВ-разделов |
| `mail` | SMTP для почтовой отправки |
| `stroka` | Параметры соответствующего модуля |

Создать хеш нового пароля:

```bash
php -r 'echo password_hash("NEW_STRONG_PASSWORD", PASSWORD_DEFAULT), PHP_EOL;'
```

Создать случайный секрет для механизма запоминания входа:

```bash
php -r 'echo bin2hex(random_bytes(32)), PHP_EOL;'
```

Храните рабочие секреты вне репозитория. Для Telegram-токена пример конфигурации также поддерживает переменную окружения `TELEGRAM_BOT_TOKEN`.

## Работа с ЕРИП

### Просмотр платежей

Веб-страница `?module=erip` предназначена для просмотра импортированных платежей из `erip_payments`: поиск по абоненту, адресу, лицевому счёту и идентификатору операции, фильтр дат, общие и дневные суммы. Информация о подключениях/обменах считывается из `erip_sync_logs`.

Доступ к модулю ограничен разрешёнными пользователями (`admin` и `kassa` в проверенной ревизии).

**Важно:** веб-отображение платежей и проверка уведомлений не равны загрузке платёжных файлов. Механизм импорта, FTP-доступ и фактическое расписание синхронизации нужно проверять отдельно в рабочем окружении.

### Уведомления по платежам

Скрипт `cron/check_erip.php` обрабатывает:

- оплаты абонентов **после** активного отключения, сопоставляя `erip_payments.account` с `master_otkluchki.personal`;
- платежи за объявления (услуга с кодом `2`), с защитой от повторов по `operation_id`;
- доставку уведомлений через включённые Telegram и/или MTS SMS;
- историю отправок и повторных попыток в `master_erip_alerts`.

Для исключения параллельных запусков используется файловая блокировка `cron/check_erip.lock`.

Безопасная диагностическая проверка **без отправки сообщений и без изменения БД**:

```bash
php cron/check_erip.php --dry-run
```

Рабочий запуск (**может отправить сообщения и изменить журнал уведомлений**):

```bash
php cron/check_erip.php
```

`--dry-run` проверяет формирование уведомлений по уже имеющимся платежам; он **не запускает импорт** платёжных файлов.

## Плановые задачи

Основной CLI-скрипт — `cron/cron1min.php`. Пример записи в crontab для установки, где приложение находится по указанному пути:

```cron
* * * * * /usr/bin/php /var/www/master2.trianda.by/cron/cron1min.php >> /var/log/master2-cron.log 2>&1
```

**Путь `/var/www/master2.trianda.by` прописан также внутри `cron1min.php` как `$BASEDIR`.** Если код развёрнут в другом месте, сначала скорректируйте его и пути к ресурсам; не копируйте cron-запись без проверки.

| Когда | Операция |
| --- | --- |
| Каждую минуту | Вызов `check_erip.php` (оплаты отключённых абонентов и объявлений) |
| Каждую минуту | Проверка включённых ридеров из `master_readers` и попытка запуска неработающих |
| Ежечасно, на 25-й минуте | Обновление `assets/meteo.png` через `wkhtmltoimage` |
| Ежедневно, 00:03 | Запуск `cleanup_database.php` |
| Первое число каждого месяца | Вызов `reports_monthly.php` (дальнейшие условия контролирует сам скрипт) |
| Ежедневно, 09:30 | Отправка подходящих записей `trianda_stroka` в Telegram |

**Импорт ЕРИП не подтверждён как часть этого ежеминутного скрипта.** Проверьте отдельные задачи синхронизации и журнал импорта на рабочем сервере.

Полезные команды для эксплуатации:

```bash
crontab -l
php cron/check_erip.php --dry-run
php -l cron/cron1min.php
```

Не запускайте диагностические команды, изменяющие БД или отправляющие сообщения, на production без понимания побочных эффектов.

## База данных

Система работает с историческими и операционными таблицами существующей БД, включая:

| Таблица | Содержание |
| --- | --- |
| `master_database` | Исторические снимки данных абонентов и задолженности |
| `master_zayavki`, `master_podkluchki` | Заявки и подключения |
| `master_otkluchki` | Отключения/восстановления |
| `erip_payments` | Импортированные платежи ЕРИП |
| `erip_sync_logs` | История синхронизации ЕРИП |
| `master_erip_alerts` | Состояние доставки уведомлений по платежам |
| `master_readers` | Настройки управляемых ридеров |
| `master_sms` | SMS-операции |
| `master_karandash`, `master_doma` | Заметки и дома |
| `master_reports`, `master_users_stat` | История отчётов и действий пользователей |

Снижение задолженности между историческими снимками позволяет обнаруживать оплаты, увеличение — начисления. Для корректной работы важны фактические типы полей, индексы и согласованность данных в рабочей БД.

Перед изменениями схемы создавайте резервную копию и проверяйте совместимость запросов в репозиториях и модулях.

## Разработка

При изменении существующего модуля обычно затрагиваются:

1. `app/index/modules.php` — выборки и данные страницы.
2. `app/index/main_actions.php` и `app/index/ajax.php` — действия и AJAX-обработчики.
3. `app/views/modules/<module>.php` — HTML, CSS и JavaScript.
4. `app/Repositories/` и сервисы в `app/` — доступ к данным и бизнес-операции.
5. `cron/` — фоновые процессы, если это необходимо.

Перед отправкой изменений проверяйте `php -l` для изменённых PHP-файлов, права на серверные действия, корректность SQL-параметров и экранирование HTML. Для операций ЕРИП проверяйте повторную обработку платежей, дедупликацию уведомлений и даты событий. Для Readers — контроль разрешений на управление ОС-процессами.

**Исходники:** [github.com/unidiag/master2](https://github.com/unidiag/master2). Для сообщений об ошибках и предложений используйте [Issues](https://github.com/unidiag/master2/issues) при наличии соответствующего доступа.

## Безопасность

- Не публикуйте `config.local.php`, пароли БД, SMS/Telegram/SMTP-ключи и адреса администрирования оборудования.
- Обязательно замените демонстрационные значения из `config.example.php`.
- Обеспечьте авторизацию, проверку прав на сервере, защиту операций изменения состояния от CSRF и безопасное отображение пользовательского ввода.
- Запретите прямой доступ извне к `cron/`, конфигурационным файлам, служебным каталогам и логам.
- Ограничьте права ОС для PHP и cron до необходимых; учтите запись блокировки `cron/check_erip.lock` и доступ к каталогам ридеров.
- Не публикуйте реальные персональные данные абонентов, платёжные файлы и содержимое журналов.
- Используйте HTTPS, резервные копии БД и контроль ошибок фоновых заданий.
