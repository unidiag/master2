# Master2

Веб-интерфейс для работы с абонентской базой, заявками, подключениями и техническими задачами кабельного оператора.

Проект является переработанной версией старой системы **Master** и рассчитан на работу с существующей базой данных. Основной интерфейс реализован на PHP без тяжёлого фреймворка и использует единый вход через `index.php`.

## Возможности

### Заявки

Модуль:

```text
?module=zayavki
```

Работа с заявками абонентов: просмотр, поиск и изменение состояния заявок.

### Подключения

Модуль:

```text
?module=podkluchki
```

Учёт заявок на подключение и связанных с ними данных.

### Абонентская база

Модуль:

```text
?module=database
```

Просмотр и поиск абонентов, лицевых счетов, адресов, тарифов, задолженности и истории изменений.

Для отключённых абонентов отображается активное отключение из `master_otkluchki`.

### Статистика по домам

Модуль:

```text
?module=stat
```

Позволяет:

- просматривать список домов;
- видеть количество абонентов и проникновение услуг;
- смотреть общую задолженность по дому;
- открывать список квартир;
- сортировать квартиры по задолженности;
- группировать квартиры;
- переходить в карточку конкретного абонента;
- просматривать историю оплат и начислений;
- хранить информацию по дому;
- выполнять контроль дома;
- работать с QR-кодами ящиков;
- отмечать отключение и восстановление абонента.

Пример:

```text
?module=stat&house=Энергетиков-16
```

Карточка абонента:

```text
?module=stat&house=Энергетиков-16&personal=5677
```

### Отключения абонентов

Отключения хранятся в таблице:

```text
master_otkluchki
```

Основные поля:

```text
created_at
deleted_at
address
subscriber
personal
tariff
summ
```

Активным считается отключение:

```sql
deleted_at IS NULL
```

При отключении:

- создаётся новая запись в `master_otkluchki`;
- квартира помечается красным цветом;
- при действующем договоре отправляется уведомление в Telegram.

При восстановлении:

- устанавливается `deleted_at`;
- событие остаётся в истории;
- при восстановлении из карточки абонента отправляется уведомление в Telegram.

Если повторное действие с карточки квартиры выполнено в течение 60 секунд после отключения, запись считается ошибочной и удаляется физически из `master_otkluchki`.

В истории абонента:

- `created_at` показывается как событие **Отключение**;
- `deleted_at` — как событие **Снято отключение**.

### Должники

Модуль:

```text
?module=debtors
```

Показывает должников с группировкой по домам.

Поддерживается фильтрация по давности последней оплаты.

Если у абонента есть активная запись в `master_otkluchki`, рядом с ним отображается дата и время отключения.

### Карандаш

Модуль:

```text
?module=karandash
```

Используется для временных заметок и отметок по абонентам.

Запись на карандаше также отображается в карточках квартир и в карточке абонента.

### Строка

Модуль:

```text
?module=stroka
```

Работа с оперативным списком записей и их состояниями.

### График

Модуль:

```text
?module=graph
```

Отображение статистических данных абонентской базы.

### Аналог / Цифра

Модули:

```text
?module=analog
?module=digital
```

Технические страницы для работы с аналоговым и цифровым оборудованием.

### SMS

Модуль:

```text
?module=sms
```

Интеграция с MTS Communicator API.

Поддерживаются отправка SMS, коды подтверждения, журнал сообщений и получение состояния доставки.

### Terminal

Модуль:

```text
?module=terminal
```

Технический интерфейс для внутренних операций.

## Telegram

Проект умеет отправлять сообщения в Telegram, в частности:

- уведомления об отключении абонента;
- уведомления о восстановлении абонента;
- сообщения о выполнении контроля дома.

Настройки находятся в секции `telegram` конфигурационного файла.

Рекомендуется передавать токен бота через переменную окружения `TELEGRAM_BOT_TOKEN`.

## Требования

- PHP 7.4 или новее;
- PDO;
- `pdo_mysql`;
- MariaDB или MySQL;
- Apache или Nginx.

Для отдельных функций также требуется доступ к Telegram Bot API, MTS Communicator API и внутреннему сетевому оборудованию.

## Установка

```bash
git clone https://github.com/unidiag/master2.git
cd master2
cp config.example.php config.local.php
```

После этого необходимо указать параметры базы данных и авторизации в локальной конфигурации.

Создать хеш пароля:

```bash
php -r "echo password_hash('НовыйПароль', PASSWORD_DEFAULT), PHP_EOL;"
```

Создать случайный `remember_secret`:

```bash
php -r "echo bin2hex(random_bytes(32)), PHP_EOL;"
```

## База данных

Master2 работает с существующей базой Master.

Используются в том числе таблицы:

```text
master_zayavki
master_podkluchki
master_database
master_sms
master_otkluchki
```

Проект не запускает автоматические SQL-миграции. Изменения структуры базы выполняются администратором вручную.

## HTTP-модули

```text
?module=zayavki
?module=podkluchki
?module=database
?module=stroka
?module=graph
?module=stat
?module=debtors
?module=karandash

```

Названия и загрузка данных модулей определяются в `app/index/modules.php`.

POST-действия разделены между:

```text
app/index/main_actions.php
app/index/stat_actions.php
app/index/stroka_actions.php
```

## Особенности интерфейса статистики

На странице квартир дома:

- обычный клик открывает абонента;
- ПКМ на компьютере переключает состояние отключения;
- долгое нажатие на телефоне выполняет то же действие;
- для карточек отключено выделение текста и iOS touch callout;
- активное отключение отображается красным номером квартиры.

Источником состояния отключения является таблица `master_otkluchki`.

## Безопасность

POST-запросы используют CSRF-проверку.

Токены Telegram, пароли базы данных и учётные данные внешних сервисов не следует коммитить в публичный репозиторий.

Для production рекомендуется отключить вывод PHP-ошибок пользователю, писать ошибки в журнал и хранить секреты вне публичной конфигурации.

## Разработка

При изменении функциональности обычно затрагиваются три уровня:

```text
app/index/modules.php
```

```text
app/index/*_actions.php
```

Обработка POST/AJAX-действий.

```text
app/views/modules/*.php
```

HTML и JavaScript конкретного модуля.
