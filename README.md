# Master2

Master2 — внутренний веб-интерфейс для работы с абонентской базой, заявками, подключениями, задолженностью, отключениями, статистикой по домам и техническими задачами кабельного оператора.

Проект является переработанной версией старой системы Master и рассчитан на работу с существующей базой данных. Приложение написано на PHP без тяжёлого фреймворка и использует единый вход через `index.php`.

## Основные возможности

### Заявки

Модуль:

```text
?module=zayavki
```

Поддерживает:

- просмотр и поиск заявок;
- создание и редактирование;
- завершение заявок;
- отображение активного отключения абонента;
- переход в статистику дома через кнопку «Обзор»;
- предупреждение о должниках в соседних квартирах;
- поиск соседних должников только для активных заявок.

Для кнопки «Обзор» проверяются квартиры вокруг текущей квартиры. В середине дома используется диапазон `±10`, а возле начала или конца дома диапазон компенсируется в противоположную сторону.

Например для дома на 100 квартир:

```text
квартира 1   -> 2..21
квартира 50  -> 40..60, кроме 50
квартира 100 -> 80..99
```

### Подключения

Модуль:

```text
?module=podkluchki
```

Используется для учёта подключений абонентов.

Поддерживаются поиск, редактирование, завершение, активные отключения, переход в статистику дома и предупреждение о соседних должниках.

### Абонентская база

Модуль:

```text
?module=database
```

Позволяет искать абонента по лицевому счёту, ФИО, адресу и телефону, просматривать тариф, текущую задолженность и историю изменений, а также импортировать и экспортировать абонентскую базу.

Фильтры:

```text
Все
Без начислений
Без оплаты
С переходящим долгом
```

#### Без начислений

Выбираются абоненты, у которых за анализируемую историю задолженность ни разу не увеличивалась.

#### Без оплаты

Выбираются абоненты, у которых задолженность ни разу не уменьшалась.

#### С переходящим долгом

Выбираются абоненты, которые платят, но после оплаты задолженность всё равно остаётся положительной.

Критерии:

- текущий долг больше `0`;
- за последние 6 месяцев была хотя бы одна оплата;
- оплатой считается уменьшение `summ`;
- после каждой найденной оплаты задолженность оставалась больше `0`.

### Статистика по домам

Модуль:

```text
?module=stat
```

Пример:

```text
?module=stat&house=Панчука-16
```

Поддерживаются:

- список домов;
- агрегированная статистика;
- список квартир;
- сортировка по задолженности;
- группировка квартир;
- переход в карточку абонента;
- история оплат и начислений;
- история отключений;
- заявки и подключения абонента;
- заметки «Карандаш»;
- QR-коды;
- контроль дома;
- отключение и восстановление абонента;
- объединение дробных номеров квартир;
- переход к квартире через URL hash.

Пример:

```text
?module=stat&house=Панчука-16#45
```

При возврате из карточки абонента ссылка «Квартиры дома» содержит hash текущей квартиры, поэтому список автоматически прокручивается к нужной карточке.

### Порог задолженности

Порог значимой задолженности задаётся в `config.local.php`:

```php
'stat' => [
    'nearby_debtor_min_debt' => 30,
],
```

Он используется для:

- предупреждения о соседнем должнике в заявках;
- предупреждения о соседнем должнике в подключениях;
- визуального выделения суммы долга на странице квартир дома.

### Отключения

Модуль:

```text
?module=otkluchki
```

Отключения хранятся в таблице `master_otkluchki`.

Активным считается отключение:

```sql
deleted_at IS NULL
```

При отключении создаётся запись, квартира отмечается в интерфейсе, событие попадает в историю и при необходимости отправляется Telegram-уведомление.

При восстановлении заполняется `deleted_at`, при этом запись остаётся в истории.

### Должники

Модуль:

```text
?module=debtors
```

Показывает должников с группировкой по домам, текущую задолженность, дату последней оплаты, фильтрацию по давности оплаты и активные отключения.

### Карандаш

Модуль:

```text
?module=karandash
```

Временные заметки по абонентам. Заметка отображается также в карточках квартир и карточке абонента.

### Строка

Модуль:

```text
?module=stroka
```

Оперативный список записей и их состояний.

### График

Модуль:

```text
?module=graph
```

Статистика по абонентской базе и тарифам на основе снимков `master_database`.

### Аналог / Цифра

```text
?module=analog
?module=digital
```

Технические разделы для аналогового и цифрового телевидения.

### SMS

Модуль:

```text
?module=sms
```

Интеграция с MTS Communicator API: отправка SMS, коды подтверждения, журнал и статусы доставки.

### Money

Модуль:

```text
?module=money
```

Финансовая и абонентская статистика, исторические данные и графики.

### Readers

Модуль:

```text
?module=readers
```

Административный технический раздел для управления reader-конфигурациями, просмотра журналов, включения/отключения, перезапуска и редактирования OSCam/Wicardd.

Доступен только `admin`.

### User stat

Модуль:

```text
?module=userstat
```

Административный журнал активности пользователей.

### Отчёты

Модуль:

```text
?module=reports
```

Формирование и отправка ежемесячных отчётов дистрибьюторам.

Поддерживаются PDF, SMTP, история отправок, ручная и автоматическая отправка.

Автоматическая рассылка выполняется первого числа месяца в `00:01` за предыдущий месяц. Успешные автоматические отправки защищены от повторной отправки одного и того же периода.

## Требования

- PHP 7.4+;
- PDO;
- `pdo_mysql`;
- MySQL или MariaDB;
- Apache или Nginx.

Для отдельных функций дополнительно используются Telegram Bot API, MTS Communicator API, SMTP, Dompdf и доступ к внутреннему сетевому оборудованию.

Для генерации хеша пароля:

```bash

```

## База данных

Master2 работает с существующей базой старой системы Master.

Основные таблицы:

```text
master_database
master_zayavki
master_podkluchki
master_otkluchki
master_sms
master_karandash
master_doma
master_money
master_reports
master_users_stat
```

Автоматических SQL-миграций нет. Изменения структуры БД выполняются вручную.

### master_database

`master_database` хранит исторические снимки абонентской базы.

Поле `update` содержит Unix timestamp снимка. Последний снимок используется как текущее состояние.

История применяется для поиска оплат и начислений, определения последней оплаты, построения графиков и анализа переходящей задолженности.

Уменьшение `summ` относительно предыдущего снимка считается оплатой. Увеличение `summ` считается начислением.

## Импорт и экспорт базы

Импорт поддерживает старый TXT-формат с разделителем:

```text
^
```

Новый импорт получает текущий Unix timestamp как номер снимка.

Экспорт формирует совместимый TXT-файл в Windows-1251 и учитывает активный поиск и выбранный фильтр.

## Cron

Основной cron:

```text
cron/cron1min.php
```

Предполагаемый запуск:

```cron
* * * * * /usr/bin/php /path/to/master2/cron/cron1min.php
```

Отдельные задачи запускаются из `cron1min.php`, включая ежемесячные отчёты и обслуживание исторических данных.

## Отчёты

Общая логика формирования и отправки отчётов вынесена в:

```text
app/ReportService.php
```

Она используется как веб-интерфейсом, так и cron.

История отправок записывается в `master_reports`.

## Особенности страницы квартир

- обычный клик открывает карточку абонента;
- ПКМ переключает состояние отключения;
- долгое нажатие на мобильном устройстве выполняет аналогичное действие;
- URL hash прокручивает страницу к конкретной квартире;
- выбранная квартира визуально выделяется;
- значительная задолженность мигает красным;
- государственный/социальный пакет имеет отдельное оформление;
- дробные номера могут объединяться в одну физическую квартиру.

## Соседние должники

Для активных заявок и подключений выполняется проверка соседних квартир.

Порог:

```php
$config['stat']['nearby_debtor_min_debt']
```

Если рядом найден должник с суммой не ниже порога, кнопка «Обзор» получает предупреждающее оформление.

Данные квартир дома кэшируются на время обработки страницы, чтобы не выполнять одинаковые запросы повторно.

## Безопасность

В проекте используются авторизация, CSRF-проверка POST-запросов, экранирование HTML и отдельная локальная конфигурация для секретов.

Не следует коммитить пароли БД, SMTP-пароли, Telegram bot token, ключи SMS API и внутренние учётные данные оборудования.

Для production рекомендуется отключить показ PHP-ошибок пользователю, писать ошибки в журнал, ограничить административные разделы и разрешать cron-скрипты только из CLI.
