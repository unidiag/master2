# Master2

**Master2** — внутренняя информационная система кабельного оператора для работы с абонентской базой, заявками, подключениями, задолженностью, отключениями, платежами ЕРИП, статистикой, техническим оборудованием и служебными уведомлениями.

Проект развивает предыдущую систему Master и использует существующую базу MySQL/MariaDB. Backend и серверные представления написаны на PHP без крупного фреймворка; основная веб-точка входа — `index.php`.

> Документация актуализирована по коммиту [`cdd46895db086c1eebb091511d4dd840429fb301`](https://github.com/unidiag/master2/commit/cdd46895db086c1eebb091511d4dd840429fb301). При развёртывании проверьте локальные настройки, структуру таблиц и пути cron-заданий.

### Абонентская база и задолженность

В `database` доступны фильтры **«Все»**, **«Без начислений»**, **«Без оплаты»** и **«С переходящим долгом»**. Переходящая задолженность определяется по историческим снимкам: текущий долг положительный, за последние шесть месяцев присутствовали уменьшения долга (оплаты), но после них долг оставался положительным.

В заявках и подключениях предусмотрена проверка ближайших квартир на значительную задолженность. Порог задаётся настройкой:

```php
'stat' => [
    'nearby_debtor_min_debt' => 30,
],
```

В статистике дома можно открыть квартиру по ссылке вида `?module=stat&house=Панчука-16#45`. Доступны история оплат и начислений, отключения, заметки, группировка дробных номеров квартир и визуальное выделение должников.

### Отключения

Отключения хранятся в `master_otkluchki`. Запись считается активной, пока `deleted_at IS NULL`; при восстановлении фиксируется время завершения, но история сохраняется. Для задач уведомления об оплате дополнительно учитывается видимость отключения (`hidden_at`).

### Readers

Административный модуль управляет reader-процессами и конфигурациями OSCam/Wicardd: журналы, состояние, запуск/остановка, перезапуск и редактирование конфигурационных файлов. Ежеминутный cron также проверяет запущенные процессы включённых ридеров.

## ЕРИП: платежи и синхронизация

### Веб-модуль

**URL:** `index.php?module=erip`  
**Представление:** `app/views/modules/erip.php`

Веб-раздел позволяет контролировать платежи, поступающие через систему ЕРИП, и состояние синхронизации:

- дата последнего успешного подключения и последней синхронизации;
- результат последней попытки соединения, количество найденных и перемещённых файлов/объектов, текст ошибки (если есть);
- общее количество платежей и общая сумма в BYN;
- количество и сумма платежей за сегодня;
- поиск по лицевому счёту, ФИО, адресу и идентификаторам операции;
- фильтрация по диапазону дат;
- таблица с датой, услугой, лицевым счётом, плательщиком, адресом, периодом, суммой, операцией, каналом и исходным файлом/строкой;
- переход по адресу к статистике дома.

В таблице используются обозначения услуг `TV` (код `1`) и `ADV` (код `2`). Запись об исходном файле и номере строки помогает сверять импортированный платёж с первичным документом.

В интерфейсе также предусмотрен индикатор следующего обновления и автоматическая перезагрузка страницы после завершения его отсчёта. В указанном коммите отсчёт привязан к последнему успешному подключению и составляет **301 секунду (~5 минут)**. Это **интервал интерфейсного обновления**, а не подтверждение того, что обмен с ЕРИП выполняется каждую минуту.

### Откуда берутся данные

Модуль отображает платежи из таблицы `erip_payments` и служебные сведения о последней синхронизации. Загрузка и разбор файлов платежей — отдельный этап обмена с ЕРИП; настройка FTP, реквизитов доступа и расписания конкретного импортёра должна проверяться по фактическим серверным заданиям.

### Контроль оплат отключённых абонентов

**Скрипт:** `cron/check_erip_disconnects.php`.

Система автоматически сопоставляет поступившие платежи ЕРИП с активными отключениями:

- `erip_payments.account` сопоставляется с `master_otkluchki.personal`;
- платёж должен быть положительным и совершённым **после** даты отключения;
- отключение должно оставаться активным (`deleted_at IS NULL`) и видимым;
- при совпадении формируется уведомление с абонентом, адресом, лицевым счётом, суммой, временем оплаты и отключения;
- используются включённые каналы уведомлений: **Telegram** и/или **SMS MTS**;
- история результатов записывается в `master_erip_alerts`, что предотвращает повторную успешную отправку одному получателю по одному платежу и отключению;
- предусмотрены блокировка параллельных запусков и учёт неудачных попыток.

Для безопасной проверки без отправки сообщений и изменения БД:

```bash
php cron/check_erip_disconnects.php --dry-run
```

Для непосредственного выполнения:

```bash
php cron/check_erip_disconnects.php
```

> `--dry-run` относится к проверке уведомлений об оплате отключённых абонентов, а не к загрузке данных ЕРИП.

## Автоматизация и cron

### Основной ежеминутный цикл

**Скрипт:** `cron/cron1min.php`. Он выполняется только через PHP CLI и подключает окружение приложения.

Пример записи в пользовательском crontab:

```cron
* * * * * /usr/bin/php /var/www/master2.trianda.by/cron/cron1min.php >> /var/log/master2-cron.log 2>&1
```

Проверьте путь `/var/www/master2.trianda.by` перед установкой; в коде `cron1min.php` он также используется как `$BASEDIR`.

При каждом запуске основной скрипт:

1. Вызывает `check_erip_disconnects.php` и проверяет новые оплаты отключённых абонентов; ошибки этого шага пишет в PHP error log.
2. Проверяет процессы включённых ридеров из `master_readers` и при необходимости пытается запустить отсутствующие.
3. Выполняет дополнительные задачи по условиям времени.

### Периодические задачи основного cron

| Период | Действие |
|---|---|
| Каждую минуту | Проверка оплат отключённых абонентов и состояния ридеров |
| Ежечасно на 25-й минуте | Обновление изображения погоды `assets/meteo.png` через `wkhtmltoimage` |
| Ежедневно в 00:03 | Вызов `cron/cleanup_database.php` |
| В первое число месяца | Вызов `cron/reports_monthly.php`; сам скрипт отчётов управляет сроками и защитой от дублирования |
| В 09:30 | Отправка подходящих записей `trianda_stroka` в Telegram |

**Важно:** ежеминутное выполнение `cron1min.php` подтверждено кодом, но автоматический **импорт файлов ЕРИП каждую минуту** в нём не обнаружен. Не следует путать проверку уже импортированных платежей с загрузкой новых файлов. Если импорт настроен отдельным crontab-заданием на сервере, его необходимо документировать отдельно, указав реальный путь к скрипту и частоту запуска.

### Проверка расписания и журналов

```bash
crontab -l
php -l cron/cron1min.php
php -l cron/check_erip_disconnects.php
php cron/check_erip_disconnects.php --dry-run
```

Запускайте cron от пользователя с правами на чтение конфигурации, доступ к БД, необходимые файлы и (для ридеров) управление процессами. Следите за PHP error log и журналом cron.

## Требования и установка

- PHP **7.4+** и расширения `PDO`, `pdo_mysql`;
- MySQL/MariaDB и доступ к базе старой системы Master;
- Apache либо Nginx с PHP;
- PHP CLI и cron для фоновых задач;
- дополнительные сервисы по используемым функциям: Telegram Bot API, MTS Communicator, SMTP, Dompdf, `wkhtmltoimage`, reader-процессы и доступ к источнику файлов ЕРИП.

```bash
git clone https://github.com/unidiag/master2.git
cd master2
cp config.example.php config.local.php
```

Заполните локальную конфигурацию, настройте веб-сервер, права доступа, подключение к БД и требуемые внешние сервисы. Прежде чем запускать производственный cron, проверьте адреса, пути и существование необходимых таблиц.

## Конфигурация

Пример параметров расположен в `config.example.php`, рабочие значения — в `config.local.php` и `config.php` согласно механизму загрузки конфигурации проекта.

Основные группы настроек: `app`, `database`, `auth`, `telegram`, `channels`, `digital`, `mts_sms`, `stat`, `money`. Для уведомлений ЕРИП используются включение Telegram/SMS, `telegram.bot_token`, `telegram.chat_ids` и `mts_sms.notification_phone`.

Пароль пользователя хранится в виде хеша:

```bash
php -r "echo password_hash('НовыйПароль', PASSWORD_DEFAULT), PHP_EOL;"
```

Генерация секрета для функции запоминания входа:

```bash
php -r "echo bin2hex(random_bytes(32)), PHP_EOL;"
```

## База данных

Приложение использует исторические и операционные таблицы существующей базы, в том числе:

| Таблица | Назначение |
|---|---|
| `master_database` | Снимки абонентской базы и история изменений задолженности |
| `master_zayavki`, `master_podkluchki` | Заявки и подключения |
| `master_otkluchki` | Отключения и восстановления |
| `erip_payments` | Загруженные платежи ЕРИП |
| `master_erip_alerts` | Журнал уведомлений о платежах отключённых абонентов |
| `master_readers` | Управляемые ридеры |
| `master_sms` | SMS-операции |
| `master_karandash` | Заметки |
| `master_doma` | Дома |
| `master_money` | Финансовые данные |
| `master_reports` | История отправки отчётов |
| `master_users_stat` | Активность пользователей |

У `master_database` поле `update` содержит Unix timestamp снимка; последний снимок определяет текущее состояние. Уменьшение поля `summ` между снимками трактуется как оплата, увеличение — как начисление. Приложение не предполагает универсального механизма автоматических SQL-миграций: структуру и индексы необходимо сверять с действующей БД.

Импорт абонентской базы поддерживает старый текстовый формат с разделителем `^`; экспорт выполняется в TXT/Windows-1251 с учётом поиска и фильтров.

## Безопасность

- Не добавляйте в Git `config.local.php`, реальные пароли БД, FTP/ЕРИП, SMTP, Telegram token, ключи MTS и учётные данные оборудования.
- Используйте проверку авторизации, CSRF-защиту для изменений и экранирование пользовательских данных в HTML.
- Закрывайте прямой HTTP-доступ к `cron/`, `terminal/`, конфигурации и служебным каталогам.
- Запускайте служебные задания через CLI и под отдельной учётной записью с минимальными правами.
- Не публикуйте исходные платёжные файлы и журналы с персональными данными.
- Контролируйте ошибки синхронизации ЕРИП, повторные попытки уведомлений и состояние основного cron.

## Разработка

При добавлении модуля обычно изменяются:

1. `app/index/modules.php` — подготовка данных страницы;
2. `app/index/*_actions.php` и `app/index/ajax.php` — POST/AJAX-операции;
3. `app/views/modules/*.php` — HTML, стили, JavaScript;
4. `app/Repositories.php` — запросы и выборки;
5. `cron/*.php` — автоматические проверки, импорт и регламентные задания.

После правок PHP полезно выполнять `php -l путь/к/файлу.php`. Перед изменением логики ЕРИП проверяйте идентификаторы платежей, дедупликацию уведомлений, границы времени платежа и отключения, а также корректность повторной обработки файлов.
